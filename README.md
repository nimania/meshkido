# مشکی‌دو | MeshkiDo

مرجع فارسی سریال‌های **در حال پخش ایران** — فاز اول.

**نشانی سایت پس از فعال‌سازی GitHub Pages:** https://nimania.github.io/meshkido/

## محدودهٔ فاز اول

فقط مجموعه‌های **داستانی ایرانی با قسمت‌های تازه**؛ نمایش خانگی و تلویزیون. بازپخش، مسابقه، تاک‌شو و آرشیو قدیمی فعلاً خارج‌اند.

ساختار مستقل از `nimania/meshkimedia` است. کد و داده و گردش‌کار مشکی‌دو هیچ تغییری در مشکی‌مدیا نمی‌دهند.

## معماری

- `data/series.json`: پروندهٔ سریال‌ها و شواهد پخش، منبع تصویر و پیوند امتیاز بیرونی (در صورت داشتن دادهٔ معتبر)
- `data/episodes.json`: فقط قسمت‌هایی که انتشارشان با منبع تأیید شده؛ شمارهٔ هر قسمت، عنوان، منبع، عکس اختصاصی (در صورت وجود) و لینک تماشا
- `data/pavaraghi.json`: متن‌های تحریریهٔ تأییدشده با سطح شواهد، هشدار اسپویل، منبع و متن مستقل
- `data/platforms.json`: نشانه‌ها و پالت‌های رنگیِ پلتفرم‌ها، پیوند به منبع لوگو
- `data/updates.json`: خبرهای کوتاه مستند و لینک منبع
- `scripts/build.mjs`: تولید صفحات مستقل SEO و نقشهٔ سایت، بدون وابستگی npm
- `public/`: ظاهر/جاوااسکریپت عمومی، انتخاب روز تقویم و بخش «امروز» با وقت تهران
- `.github/workflows/pages.yml`: ساخت و انتشار GitHub Pages

ساخت محلی: `node scripts/build.mjs`؛ خروجی در `dist/`. برای انتشار، GitHub Settings → Pages → Build and deployment → Source را **GitHub Actions** انتخاب کنید. سپس Actions → Deploy MeshkiDo → Run workflow را اجرا کنید (یا commit جدید بزنید).

## پاورقی مشکی‌دو

- `/pavaraghi/` صفحهٔ مرکزی، `/pavaraghi/<series>/` صفحهٔ هر سریال و `/pavaraghi/<series>/<slug>/` صفحهٔ نوشتهٔ منتشرشده است.
- پرونده‌های قسمت‌ها به‌صورت خودکار در صف بررسی دیده می‌شوند؛ «در صف بررسی» یک **مقالهٔ تولیدشده یا تأییدشده نیست**.
- فقط مقاله‌های `status: published` که دست‌کم سه بند مناسب و منبع HTTPS دارند، صفحهٔ مستقل می‌گیرند. مدل داده از `series-intro` (پیش‌درآمد بدون ادعای تماشای قسمت) و `episode-recap` (روایت قسمت با کنترل شواهد) پشتیبانی می‌کند.
- در شروع یک پیش‌درآمد مستند برای فصل دوم «روشنایی شب» منتشر شده است. این **جایگزین پاورقی قسمت اول نیست**.
- اتصال صوت/ویدئو، انتشار در شبکه‌های اجتماعی و تولید خودکار متن هنوز فعال نیستند. استاندارد کامل: `PAVARAGHI_EDITORIAL_STANDARD.md`.

## اصول صحت محتوا

1. هیچ عدد بازدید یا ریتینگی بدون منبع معتبر ایجاد نمی‌شود.
2. روز هفتگی پخش، **تضمین انتشار قسمت مشخصی در آینده نیست**؛ شماره قسمت یا تاریخ انتشار جدید فقط پس از تأیید درج شود.
3. هر سریال منبع، نام پلتفرم، زمان آخرین بررسی و وضعیت مستند دارد.
4. خبرهای منابع دیگر بازنشر کامل نمی‌شوند؛ فقط توضیح فارسی اصیل با لینک به منبع.
5. برای تصاویر قسمت‌ها، عکس اختصاصی باید با منبع همان قسمت ثبت شود؛ تا پیش از آن پوستر یا تصویر آرشیوی **با برچسب روشن** به‌عنوان تصویر سریال نمایش داده می‌شود.
6. با پایان پخش، وضعیت به `تمام‌شده` تغییر می‌کند؛ برای فاز اول دیگر در فهرست فعال نمایش داده نمی‌شود، ولی صفحهٔ اختصاصی حفظ می‌شود.
7. با قدیمی‌شدن منابع، سایت برچسب زمان آخرین بررسی را نمایش می‌دهد؛ «به‌روز» بدون شاهد اعلام نمی‌کند.

## اصول طراحی تقویم و قسمت‌ها

- «منتشرشدهٔ امروز»: تنها وقتی در `episodes.json` تاریخ دقیق تأییدشده برابر تاریخ تهران باشد.
- «برنامهٔ امروز»: روز معمول انتشار؛ **دلیل بر در دسترس بودن قسمت تازه نیست**.
- «روی آنتن امشب»: برای تلویزیون، با برچسب برنامهٔ اعلام‌شده.
- تقویم تب‌دار ۷ روزه با شمارش واقعی عنوان‌ها، دو ستون نمایش خانگی و تلویزیون.
- صفحه مستقل هر قسمت در `/series/<slug>/episode/<number>/`؛ در صورت فصل مستقل از `/episode/season-N-<number>/` برای جلوگیری از تداخل.
- تصویر پوستر از منابع ثبت‌شده در JSON به‌صورت پیوند نمایشی با اعتباردهی استفاده می‌شود. اگر تصویر غایب یا غیردسترس بود کارت جایگزین گرافیکی است. حق بازنشر عکس‌ها متعلق به صاحبان آثار است.
- لوگوهای قابل‌راستی‌آزماییِ فیلیمو و شبکه یک از Wikimedia Commons؛ برای نشان‌های فاقد فایل قابل‌تأیید از نوشتهٔ نام پلتفرم استفاده می‌شود، نه لوگوی ساخته‌شدهٔ مشابه.
- اعداد ریتینگ یا رتبه‌بندی تنها با منبع، مقیاس و تاریخ معتبر نمایش داده می‌شوند؛ امتیازِ ثبت‌نشده به معنای صفر نیست.

## به‌روزرسانی

`data/series.json` و `data/updates.json` را با خبر تأییدشده اصلاح کنید؛ commit به `main` همه صفحات را بازسازی و منتشر می‌کند. **گردآوری خبرهای تازهٔ سریال‌ها هر سه ساعت یک‌بار** با فیلتر منابع شناخته‌شده اجرا می‌شود؛ خبرهای جدید به `data/updates.json` اضافه می‌شوند. ثبت خودکار قسمت‌ها فعال نیست و فقط قسمت‌های با شاهد مستقل در `episodes.json` ثبت می‌شوند.

## نشان فعلی پروژه

لوگوی قرمز و مشکیِ ارسال‌شده توسط مالک پروژه در تاریخ ۶ آبان ۱۴۰۵، به شکل فشرده و بدون تغییر طراحی در `assets/meshkido-logo.webp` برای سربرگ، صفحهٔ اصلی و پیش‌نمایش لینک استفاده می‌شود. آیکون مرورگر از همان نشان در `assets/meshkido-favicon.png` تهیه شده است. این نشان فعلاً موقت است و می‌تواند در آینده جایگزین شود.


## کانال تلگرام مشکی‌دو

- الگو مشابه مشکی‌مدیاست: عکس در صورت وجود، تیتر، توضیح فارسی، هشتگ سریال، لینک صفحهٔ مشکیدو و لینک منبع.
- انتشار بعد از استقرار موفق صفحات انجام می‌شود و وضعیت در `data/telegram-posted.json` نگهداری می‌شود تا پیام تکراری ارسال نشود.
- نخستین اجرا فقط مطالب موجود را در وضعیت ثبت می‌کند و **هیچ آرشیو قدیمی‌ای را به کانال نمی‌فرستد**.
- تنها خبرهای دارای منبع و قسمت‌هایی با `releasedAt` ثبت‌شده در صف قرار می‌گیرند؛ برنامهٔ پخش هفتگی معادل اعلام انتشار نیست.
- در GitHub → Settings → Secrets and variables → Actions دو Secret تعریف کنید: `MESHKIDO_TELEGRAM_BOT_TOKEN` (توکن ربات جداگانه یا مشترک) و `MESHKIDO_TELEGRAM_CHAT` (نام کانال با `@` یا شناسهٔ عددی). ربات باید در کانال دسترسی ارسال پیام داشته باشد.
- کانال تلگرام را مالک باید از خود تلگرام بسازد و ربات را مدیر کند؛ اتصال GitHub به‌تنهایی کانال تلگرام ایجاد نمی‌کند.
- اجرای آزمایشی بدون ارسال: `node scripts/telegram-publish.mjs --dry-run`. تست‌ها: `node --test tests/telegram-publish.test.mjs`.
